# GA4 Merchandise Store — Analytics Dashboard

A statistical dashboard built from a Google Analytics 4 (BigQuery export) event
sample: 100,000 events, 42,610 users, Nov 1 2020 – Jan 31 2021. It covers
traffic, audience, customer journey and e-commerce statistics, plus predictive
models that forecast buyers, orders and daily sales.

## Dashboard pages

The sidebar is grouped into four sections:

| Section          | Pages                                                        |
|------------------|--------------------------------------------------------------|
| Summary          | Overview, Summary & Trends                                   |
| Audience         | Countries, Device Category, OS & Browser                     |
| Customer Journey | Traffic Sources, Events, Conversion, eCommerce               |
| Forecasting      | Forecasts & Insights, Model Accuracy                         |

The **Forecasts & Insights** page shows the 14-day forecast, the weekly pattern
(each weekday compared with an average day), odds ratios, predicted order
ranges and quiet-day flags. The **Model Accuracy** page shows each model's
scores against its baseline, model comparisons, interval coverage, recall and
training vs. test results.

## Files

| File            | Purpose                                                                |
|------------------|------------------------------------------------------------------------|
| `build_data.py`  | Python. Reads `BigQuery_4M_100k_cleaned.csv`, computes descriptive statistics (frequency, central tendency, dispersion, position), and writes `data.json` + `stats_report.md`. |
| `GMS_Predictive_Models.ipynb` | Google Colab notebook. Trains and evaluates the predictive models for Problems #1–#4 (Section 5 of the Problem Statement) and exports `predictions.json`. |
| `predictions.json` | Generated by the notebook and included in the repo. Read by the two **Forecasting** pages. |
| `data.json`      | Generated. Compact integer-coded event table + lookups the dashboard reads at runtime. |
| `stats_report.md`| Generated. Human-readable descriptive statistics report (whole dataset). |
| `index.html`     | Dashboard shell: sidebar nav, date-range controls, panel containers.  |
| `styles.css`     | Layout & component styling (imports `theme.css`).                     |
| `theme.css`      | Color tokens, taken from your uploaded design system.                  |
| `app.js`         | Loads `data.json` and `predictions.json`, filters by date range, renders every chart/table with Chart.js. |
| `favicon.ico`, `favicon.svg`, `apple-touch-icon.png` | Browser tab and home-screen icons. |

## Run it

Because the dashboard fetches `data.json`, it needs to be served over HTTP
(opening `index.html` directly as a `file://` URL will be blocked by the
browser's CORS rules). From this folder:

```bash
python3 -m http.server 8000
```

Then open **http://localhost:8000** in your browser.

## Regenerating the data

`build_data.py` looks for `BigQuery_4M_100k_cleaned.csv` in this folder first,
then in the parent folder. You can also pass a path:

```bash
python3 build_data.py                       # finds the cleaned CSV automatically
python3 build_data.py path/to/cleaned.csv
```

This rewrites `data.json` and `stats_report.md`. It needs `pandas`.

## Predictive models (Google Colab)

`predictions.json` is already in the repo, so the Forecasting pages work out
of the box. To retrain the models and regenerate it:

1. Open `GMS_Predictive_Models.ipynb` in Google Colab (File → Upload notebook).
2. Choose **Runtime → Run all** and upload `BigQuery_4M_100k_cleaned.csv` when asked.
3. The last cell downloads `predictions.json`. Copy it into this folder, next to `data.json`.
4. Reload the dashboard and open **Forecasts & Insights** or **Model Accuracy**.

If `predictions.json` is missing, the Forecasting pages show these steps
instead of results. The date filter is hidden on those pages, because the
models are trained and tested on fixed periods (training Nov 1 – Jan 17,
test Jan 18 – 31 for the daily models).

## Notes on the data

- There is no page-URL / landing-page field in this export, so "Landing
  Pages" and "Top Pages" panels were left out per your request — everything
  else in the original sidebar list is included.
- `operating_system` includes a `"Web"` value — this is how GA4 reports
  desktop-web sessions in this export; it's not a bug.
- Only 133 of the 100,000 events are `purchase` events. The cleaned CSV
  filled 10 missing revenues with the $50 median (flagged in
  `purchase_missing_revenue`); those 10 are counted as orders but left out of
  the revenue statistics, so order-value figures use 123 orders, matching the
  Problem Statement (mean $71.52, median $50).
- The accent color in your uploaded CSS (`--accent: #2d397`) was an invalid
  5-digit hex code, so I substituted a teal derived from your chart palette
  (`oklch(0.65 0.14 200)`) to keep the same navy/slate/teal feel. Swap
  `--accent` in `theme.css` if you had a specific color in mind.
